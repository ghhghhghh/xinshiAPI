# xingshi-api-import Skill

把当前项目的接口导入本地「信使 API 工作台」，让用户切回信使后直接点击发送测试，不用手抄接口和参数。

> 这个文件夹随信使安装包一起分发，不需要源码仓库，也不需要 Node。MCP 服务是安装包内的 `xingshi-mcp`，由信使「设置 → AI 接入」生成配置。

## 它会做什么

- 扫描目标项目的路由、Controller、OpenAPI、请求封装和 DTO。
- 把接口整理成「项目 → 模块/文件夹 → 接口」，写入信使左侧树。
- 填好参数表：名称、类型（string / number / boolean / enum / file）、示例值、说明；枚举写入自定义选项。
- 填好 Body、Headers、鉴权。
- 在设计视图里填好返回字段（`responseLabels`）：路径、类型、中文名、说明、示例。
- 可同时创建/切换环境，填前置 URL 和变量。

## 前置条件

- 已安装并启动过信使，本地数据库存在。
- 已在信使「设置 → AI 接入」里把 MCP 配置复制到当前 AI 工具，并重启过 AI 工具。
- AI 工具能调用 `xingshi` MCP（工具名可能是 `mcp__xingshi__import_api_tree`）。

## 安装

打开信使：

1. 设置 → **AI 接入**。
2. 按你使用的工具复制 Codex 配置或 Qoder 配置，粘贴到 AI 工具的对应配置文件。配置里的 `command` 指向安装包内的 `xingshi-mcp.exe`，`args` 留空；它不是 npm 包，不需要 `npx`。
3. 点「安装 Skill 到 Qoder」；如果使用其他支持技能目录的工具，复制面板里的 Skill 路径，把整个 `xingshi-api-import` 文件夹放进去。
4. 重启 AI 工具。

Skill 的安装单位是整个文件夹（包含 `SKILL.md` 和本说明），不是单个文件。

## 使用

在任意项目里对 AI 说：

- 「把这些接口导入信使」
- 「把用户模块同步到信使」
- 「生成一套可以在信使里直接发送的接口」

AI 会先 `list_workspace`，再构造接口树，用 `import_api_tree` 的 `dryRun: true` 预览，确认后正式导入。

导入完成后切回信使：窗口重新获得焦点会自动刷新；也可以在侧栏点刷新图标。找到新接口后直接点「发送」。

## 更新

信使安装包更新后，重新打开「设置 → AI 接入」，重新复制 MCP 配置并按需重新安装 Skill。

## 边界

- 只在用户明确要导入时写入；默认不删除任何已有接口。
- 不把真实密码或生产 token 写进参数；敏感值放环境变量或登录后提取。
- 找不到响应结构时，设计视图可以留空，不要臆造字段。
